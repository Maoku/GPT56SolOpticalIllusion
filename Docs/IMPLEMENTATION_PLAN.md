# GPT-5.6 Sol Optical Illusion Museum 実装計画

## 1. 目的

`Docs/PLAN.md` の企画を、ブラウザで遊べる一人称視点の 3D ミュージアムとして実装する。

来場者は館内を自由に移動して錯視作品を鑑賞できる。各展示の「見え方のヒント」は初期状態では隠し、展示に近づいてボタンを押した場合にだけ説明を表示する。

## 2. MVP の完成像

### 体験フロー

1. タイトル画面で操作方法を確認し、「入館する」を押す。
2. 3D のロビーから展示室へ移動する。
3. 展示に近づくと、作品名、「操作する」、「見え方のヒントを見る」の各ボタンが表示される。
4. 「操作する」を押すと展示モードへ入り、ドラッグやスライダーで見え方を変えられる。
5. ヒントを明示的に押した場合だけ説明パネルを表示し、答え合わせとリセットも選べる。
6. 展示モードを終了すると、その場から探索を再開できる。
7. すべての展示を見終えたことは館内マップまたは展示一覧で確認できる。

### MVP に含める展示

最初のリリースでは、錯視原理と操作方法が重複しない次の 10 展示を用意する。外部画像は使わず、図形、シェーダー、照明、3D ジオメトリで生成する。

| # | 展示 | 錯視原理 | インタラクション | 答え合わせ |
| --- | --- | --- | --- | --- |
| 1 | ミュラー・リヤー錯視 | 矢羽による長さ知覚の変化 | 片方の線をドラッグして同じ長さに見えるよう調整する | 矢羽を外し、実長とユーザーの誤差を重ねて表示する |
| 2 | ポンゾ錯視 | 収束線による奥行きと大きさの補正 | 2 本の線を奥行き方向へ移動し、同じ長さに見える位置を探す | 遠近線を消し、2 本を横に並べる |
| 3 | エビングハウス錯視 | 周囲の円による大きさ知覚の変化 | 中央円の大きさを調整して、左右が同じに見える値を決める | 周囲円を退避し、中央円の実寸と誤差を表示する |
| 4 | カフェウォール錯視 | 明暗タイルのずれによる平行線の傾き知覚 | 行のずれと目地の太さをスライダーで変更する | 水平ガイドを重ね、線が平行であることを示す |
| 5 | チェッカーシャドウ錯視 | 影と文脈による明るさの恒常性 | 光源または影を動かし、2 タイルの見え方を変える | 同色タイルをつなぐ色帯を表示し、数値も比較する |
| 6 | ネッカーキューブ | 1 つの図形に対する奥行き解釈の反転 | 立方体をドラッグ回転し、クリックで手前面の解釈を切り替える | 奥行き手がかりと面の色を段階的に追加する |
| 7 | 運動誘発盲 | 周辺運動中の静止刺激の知覚消失 | 中央を注視し、背景の速度、密度、ターゲット数を変更する | 背景を停止し、全ターゲットの位置を再表示する |
| 8 | エイムズの部屋 | 歪んだ空間を正しい直方体に見せる強制遠近法 | 2 体の人形をレール上で動かし、鑑賞点と自由視点を切り替える | 俯瞰視点へ移り、部屋の実形状と人形の実寸を表示する |
| 9 | 視差の花（オリジナル） | 運動視差、輪郭位相、明暗対比の組み合わせ | 視点を左右へ動かし、花弁層の位相と追従量を調整する | 各層を分離し、同じ半径の図形が移動しているだけだと示す |
| 10 | 色彩残響回廊（オリジナル） | 色順応、残像、補色対比の組み合わせ | 色を選び、短い注視シーケンス後に無彩色の回廊へ進む | 順応前後と計算上の補色を並べ、残像なしモードと比較する |

「視差の花」と「色彩残響回廊」は、本プロジェクト独自の造形、演出、操作として制作する。知覚原理そのものを新発見と主張するものではなく、既知の原理を 3D ミュージアム向けに独自に組み合わせた作品とする。

各展示には以下を必須とする。

- 作品名
- 観察を促す短い問いかけ
- 初期状態で非表示のヒント
- 錯視を確認するための「答え合わせ」操作
- ドラッグ、スライダー、視点移動など、展示固有の操作
- 操作状態を初期値へ戻すリセット操作
- 展示を見たことを示す状態

各展示は「観察する」「操作して変化を試す」「答え合わせする」の 3 段階で構成する。ヒントを開かなくても操作できるようにし、説明を読む前の発見を妨げない。

## 3. スコープ

### MVP に含めるもの

- デスクトップとモバイルブラウザで動く単一ページアプリ
- 一人称視点の移動、視点操作、壁との衝突判定
- ロビー、3 つの展示ゾーン、案内サイン、10 種の錯視展示
- 展示への接近判定とフォーカス表示
- 展示固有のインタラクション、ヒントパネル、答え合わせ操作
- 操作方法、音量、視点速度、モーション軽減の設定
- 展示の閲覧状況のセッション内保存
- ローディング、WebGL 非対応、実行時エラーの案内
- 基本的な自動テストと主要端末での手動確認

### MVP に含めないもの

- ログイン、クラウド保存、ランキング
- マルチプレイヤー
- VR / WebXR 対応
- ユーザー投稿型展示
- 多言語対応。ただし文言は将来切り替えられる構造にする
- 大量の外部 3D モデルや高解像度テクスチャ

## 4. 技術方針

### 推奨スタック

- ビルド: Vite
- 言語: TypeScript（strict モード）
- UI: React
- 3D: Three.js + React Three Fiber + Drei
- 状態管理: Zustand
- スタイル: CSS Modules またはグローバル CSS とデザイントークン
- 単体・コンポーネントテスト: Vitest + Testing Library
- E2E: Playwright
- 静的解析・整形: ESLint + Prettier

React と 3D シーンを同じコンポーネントモデルで扱い、ヒント UI や設定画面と展示オブジェクトの状態を同期しやすくする。展示はデータ定義、インタラクション状態、表示コンポーネントを分離し、11 点目以降を既存コードへの変更を抑えて追加できる構造にする。

### 対象ブラウザ

- Chrome / Edge: 最新 2 バージョン
- Safari: 最新 2 バージョン
- Firefox: 最新 2 バージョン
- iOS Safari / Android Chrome: 現行メジャーバージョン

WebGL 2 を基本とし、利用できない場合は原因と推奨環境を記載したフォールバック画面を表示する。

### 展示データ

展示ごとの文言、配置、接近距離、表示コンポーネントをカタログに集約する。

```ts
type ExhibitDefinition = {
  id: string;
  title: string;
  isOriginal: boolean;
  prompt: string;
  hint: {
    summary: string;
    explanation: string;
  };
  position: [number, number, number];
  rotation: [number, number, number];
  interactionDistance: number;
  exhibitType:
    | "muller-lyer"
    | "ponzo"
    | "ebbinghaus"
    | "cafe-wall"
    | "checker-shadow"
    | "necker-cube"
    | "motion-induced-blindness"
    | "ames-room"
    | "parallax-bloom"
    | "chromatic-echo-corridor";
  interaction: {
    mode: "drag" | "slider" | "gaze" | "viewpoint" | "hybrid";
    instructions: string;
    supportsReducedMotion: boolean;
  };
};
```

表示済み状態やパネル開閉状態はカタログへ持たせず、ストア側で管理する。展示固有のパラメーターは各展示内のローカル状態とし、共通ストアには「未体験」「操作済み」「答え合わせ済み」の進捗だけを保存する。

### アプリ状態

状態は次の遷移を基本とする。

```text
起動中 -> タイトル -> 探索中 -> 展示フォーカス -> 展示操作中
                         |              |             |
                         |              +-> ヒント表示 |
                         |              +-> 答え合わせ |
                         +-------------> 設定表示 <----+
```

- 展示操作、ヒント、答え合わせ、設定の表示中は Pointer Lock とプレイヤー移動を停止する。
- パネルを閉じたら、ユーザー操作を起点として Pointer Lock を再取得する。
- フォーカス対象は毎フレームの総当たりではなく、近傍判定またはレイキャストで一つに絞る。
- 展示ごとの「未体験」「操作済み」「答え合わせ済み」は `sessionStorage` に保存し、再読み込み時に復元する。

## 6. UI / 操作設計

### デスクトップ

- `WASD` / 矢印キー: 移動
- マウス: 視点移動
- `E` またはクリック: 展示モードへ入る、決定する
- ドラッグ / 矢印キー: 展示パラメーターを変更する
- `R`: 展示を初期状態へ戻す
- `H`: ヒントを開く
- `Esc`: パネルを閉じる、または Pointer Lock を解除
- 画面中央に小さな照準を表示する

### モバイル

- 画面左側の仮想スティック: 移動
- 画面右側のドラッグ: 視点移動
- 展示フォーカス中に大きめの操作ボタンを表示する
- 展示モードでは、ドラッグ領域と値を変更できるボタンまたはスライダーを併設する
- 仮想コントローラーがヒントパネルと重ならないよう安全領域を考慮する

### ヒント表示

- 展示に近づくまでヒントボタン自体を表示しない。
- 展示操作とヒント表示は別操作にし、操作を始めただけではヒントを表示しない。
- 答え合わせはヒントパネル内と展示操作 UI の両方から明示的に実行できる。
- モーダルまたは下部シートとして表示し、背景を暗くして作品説明へ集中させる。
- キーボードフォーカスをパネル内に閉じ、閉じた後は元の操作ボタンへ戻す。
- `prefers-reduced-motion` では大きなズームや揺れを使わない。

完了条件:

- キーボード、マウス、タッチの各操作で全展示へ到達できる
- 離れた展示や背後の展示には操作ボタンが出ない

### Phase 4: 展示フレームワークと 10 展示

作業:

- `ExhibitDefinition` と展示カタログを実装する
- 共通展示枠、作品名プレート、接近判定を実装する
- ドラッグ、スライダー、注視タイマー、視点固定を共通入力として実装する
- 各展示に操作、リセット、ヒント、答え合わせ状態を追加する
- 展示を次の 3 バッチで追加する

#### Phase 4A: 縦切りと幾何錯視

- ミュラー・リヤーを使い、「接近 -> 観察 -> 操作 -> ヒント -> 答え合わせ -> リセット」の全体を縦切りで完成させる
- 共通 API の確定後、ポンゾ、エビングハウス、カフェウォールを追加する
- 画面上のドラッグ操作と 3D オブジェクト操作が競合しない入力優先順位を確定する

#### Phase 4B: 光、運動、空間の錯視

- チェッカーシャドウ、ネッカーキューブ、運動誘発盲を追加する
- 専用室と鑑賞点を持つエイムズの部屋を追加する
- 連続アニメーションは画面外、ポーズ中、モーション軽減時に停止または簡略化する

#### Phase 4C: オリジナル展示

- 「視差の花」を手続き生成し、花弁数、位相、追従量を調整可能にする
- 「色彩残響回廊」に準備、注視、観察、比較の状態遷移を実装する
- それぞれに独自のタイトル、作品文、造形、サウンド演出を用意する
- 原理を切り分けて見せる答え合わせモードを実装する

実装順は 2D 平面中心の展示、連続描画を使う展示、専用 3D 空間、オリジナル展示とする。各バッチの完了時にデスクトップとモバイルで操作を確認し、10 展示を最後にまとめて統合するリスクを避ける。

完了条件:

- 10 展示すべてで「観察 -> 操作 -> ヒント -> 答え合わせ」が成立する
- 答え合わせ後に元の錯視表示へ戻せる
- マウス、キーボード、タッチのいずれでも展示固有の操作を完了できる
- 展示間を移動した後も、各展示を意図した初期状態へリセットできる
- 展示追加がカタログ登録と専用コンポーネント追加だけで行える

### オリジナル展示の知覚検証

オリジナル 2 展示は主観的な見え方に依存するため、実装完了だけを合格条件にしない。

1. 静止画または単純形状で、組み合わせる知覚原理を個別に確認する。
2. パラメーターを調整できるプロトタイプを作り、効果が出る範囲を記録する。
3. 制作メンバー以外の少なくとも 5 人に、ヒントを見せず短時間の観察テストを行う。
4. 5 人中 4 人以上が意図した変化を報告できる設定を標準値にする。
5. 効果を感じない人でも、答え合わせと説明によって操作の目的を理解できることを確認する。

検証結果は知覚現象の科学的証明には用いず、展示として成立する初期設定の選定にだけ使用する。

### 単体テスト

- アプリ状態の遷移
- 閲覧済み状態の追加、重複排除、復元

- ヒントが初期状態で描画されないこと
- 操作ボタンからヒントを開閉できること
- 展示の操作後もヒントが自動では開かないこと
- マウス、キーボード、タッチ相当入力が同じ値へ反映されること
- パネルのフォーカストラップと `Esc` 操作
- 展示一覧の閲覧状態表示

### E2E テスト

- タイトルから入館して最初の展示のヒントを開く
- ヒント表示中に移動入力が無効になる
- 答え合わせを実行して元の展示へ戻す
- 10 展示を閲覧して完了表示を確認する
- 各展示の操作、答え合わせ、リセットをデータ駆動テストで一巡する
- ゾーン移動時の遅延ロードと状態保持を確認する
- ページ再読み込み後の状態復元
- WebGL 初期化失敗時のフォールバック

3D の見た目そのものは壊れやすい全面スナップショットに依存せず、代表視点の限定的なスクリーンショット比較と手動確認を組み合わせる。

## 9. リスクと対策

| リスク | 対策 |
| --- | --- |
| 3D 酔いが起きる | 視点揺れを使わない、視点速度を調整可能にする、モーション軽減を用意する |
| モバイル操作が難しい | 操作領域を左右に分離し、ボタンを 44 px 以上にする、実機で早期検証する |
| 照明差で錯視が成立しない | 展示ごとに独立した照明・色管理を行い、答え合わせ用の数値もテストする |
| エイムズの部屋の視点がずれる | 鑑賞ポイントで視点位置と向きをガイドし、必要なら短時間だけ固定する |
| 3D アセットでロードが重くなる | MVP はプリミティブと手続き生成を優先し、追加モデルは glTF 圧縮する |
| UI 操作と Pointer Lock が競合する | UI 表示状態を単一ストアで管理し、ロック取得・解除を状態遷移に集約する |
| 連続運動や注視課題が不快になる | 一時停止、スキップ、モーション軽減を常設し、高速点滅を使わない |
| 色覚差によって展示が成立しない | 色だけで情報を伝えず、明暗、形、ラベルを併用し、代替比較モードを用意する |
| オリジナル展示の効果が弱い | パラメーター式プロトタイプと小規模観察テストで標準値を決める |
| 10 展示で初期ロードが増える | ゾーン単位でコードとアセットを分割し、未表示のアニメーションを停止する |

## 10. マイルストーン

1. **M1: 歩ける空間** — Phase 0〜3。館内を移動し、展示位置をフォーカスできる。
2. **M2: 展示基盤** — Phase 4A。4 つの幾何錯視で共通インタラクションが動く。
3. **M3: 既知錯視完成** — Phase 4B。既知錯視 8 種の主要フローが動く。
4. **M4: オリジナル展示完成** — Phase 4C。独自作品 2 種が知覚検証を通過する。
5. **M5: MVP 完成** — Phase 5〜6。案内、進捗、モバイル、品質基準を満たす。
6. **M6: 公開** — Phase 7。本番環境で主要フローを確認する。

## 11. MVP の Definition of Done

- 対象ブラウザでタイトルから全 10 展示の閲覧完了まで進める
- ヒントはユーザーが明示的に操作するまで表示されない
- 各展示で錯視、固有のインタラクション、答え合わせ、リセットが確認できる
- オリジナル展示 2 種が定義した小規模観察テストを通過している
- デスクトップとモバイルの操作が成立する
- キーボードだけで HTML UI と展示パラメーターを操作できる
- lint、型チェック、単体テスト、E2E、production build が成功する
- 性能目標を満たし、重大なコンソールエラーがない
- 新しい展示をカタログと展示コンポーネントの追加で拡張できる

## 12. 実装開始時の最初のタスク

1. Vite + React + TypeScript を初期化する。
2. 品質コマンドと CI を用意する。
3. `MuseumScene`、アプリ状態ストア、タイトル画面の最小構成を作る。
4. 箱型の仮ミュージアムとデスクトップ移動を作る。
5. ミュラー・リヤー錯視を縦切りで実装し、「接近 -> 観察 -> 操作 -> ヒント -> 答え合わせ -> リセット」全体を検証する。
6. 縦切りで得た API を確定してから幾何錯視 3 展示とモバイル操作へ展開する。
7. 既知錯視の残り 4 展示を追加し、ゾーン単位の遅延ロードを確認する。
8. オリジナル 2 展示をパラメーター式プロトタイプとして作り、観察テスト後に本番演出へ仕上げる。
