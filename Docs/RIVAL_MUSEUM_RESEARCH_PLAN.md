# 競合美術館 調査実行計画書

## 1. 目的

`Docs/RIVAL_MUSEUM_RESEARCH.md` に記載された競合美術館を実際に鑑賞し、自館「PARALLAX」との差を、体験証拠とソース上の裏付けの両方から明らかにする。

今回の成果は、改修案を先に決めることではなく、次の判断材料を揃えた調査レポートを作ることである。

- 競合が来館者に強い印象を与える要因
- 自館がすでに優れている点と、競合に対して不足している点
- 集客・満足度・再訪意向へ影響しそうな改善機会
- 各結論を導いた観察事実、理由、証拠

## 2. 調査原則

1. **体験を先、ソース確認を後にする。** 最初の鑑賞は実装情報を追加で調べず、一般来館者として行う。
2. **ソースだけで評価しない。** ソースは位置、状態遷移、操作条件、実装意図の確認に使い、必ず実際の体験記録と組み合わせる。
3. **自館と競合を同条件で比べる。** 同じ Chrome、画面サイズ、入力方法、音量、画質、モーション設定を使用し、条件を記録する。
4. **観察・解釈・提案を分ける。** 「起きたこと」「なぜ重要と判断したか」「改善にどうつながるか」を混同しない。
5. **結論ごとに理由を残す。** 比較表の点数だけを提示せず、証拠 ID と判断理由を併記する。
6. **作品数の単純比較をしない。** 競合はトップレベル 16 展示に加えて 2D ギャラリー内に 6 作品があるため、数量、体験の深さ、独自性を別々に評価する。

## 3. 調査で答える問い

### 入館・導入

- タイトル画面から最初の展示体験まで、迷わず進めるか。
- 操作説明は、読む量と実際の行動のバランスが取れているか。
- 最初の 60 秒で、世界観と「ここで何ができるか」が伝わるか。

### 館内探索

- 展示、ビュースポット、増築棟を自力で発見できるか。
- 動線、サイン、照明、空間の変化が次の行動を導いているか。
- 移動、視点、早歩き、Pointer Lock の解除・復帰に摩擦がないか。

### 展示体験

- ヒントなしで、各錯視の見る位置と注目点が分かるか。
- `E` の視点スナップによって錯視が明確に成立するか。
- 操作可能展示では、入力、視覚変化、答え合わせの因果関係が理解できるか。
- 種明かしが驚きを壊さず、理解と再観察を促しているか。
- 既知の錯視とオリジナル作品が、量だけでなく体験の幅を作っているか。

### 見せ方・ブランド

- 建築、照明、色、タイポグラフィ、展示間隔に一貫性があるか。
- スクリーンショットや短い動画で共有したくなる場面があるか。
- 「FABLE ORIGINALS」が独自性と来館理由として機能しているか。

### 品質・包摂性

- フレーム落ち、読み込み待ち、描画破綻、操作不能、コンソールエラーがないか。
- キーボード操作、文字の可読性、色への依存、モーション負荷に問題がないか。
- 体験を中断した後、迷わず探索へ戻れるか。

## 5. 事前準備

### 5.1 セッション条件の固定

`visit-log.md` の冒頭に次を記録する。

- 調査日時、調査者
- OS、Chrome バージョン
- 画面解像度、ブラウザの表示領域、ズーム率
- マウス／トラックパッド、キーボード
- 音量、画質、モーション軽減設定
- 自館のコミット ID と起動 URL
- 競合 URL `http://localhost:4173`

競合へのアクセスは、指示どおり権限昇格した Chrome と Computer Use を用いる。自館は同じ Chrome ウィンドウ条件で起動し、セッション進捗を初期化した初回来館状態から開始する。

### 5.2 記録方式の準備

各記録に一意な ID を付ける。

- 観察: `OBS-R-001`（競合）、`OBS-S-001`（自館）
- 画面証拠: `rival-<連番>-<内容>.png`、`self-<連番>-<内容>.png`
- ソース確認: `SRC-R-001`、`SRC-S-001`
- 比較結果: `CMP-001`

画面証拠は、最低でも「場所が分かる全景」と「評価対象が読める近景」を使い分ける。操作展示は必要に応じて操作前後の 2 枚を残す。

## 6. 実行手順

### Phase 1: 競合の初見自由鑑賞

目安: 20〜30 分

1. タイトル表示から入館し、最初に理解できた操作と理解できなかった操作を記録する。
2. 展示リストやソースを見直さず、自然に目についた方向へ進む。
3. ヒントは最初の観察回答が済むまで開かない。
4. 迷った地点、立ち止まった理由、最初に操作できた展示、最初に強く驚いた展示を時刻付きで記録する。
5. 10 分時点と終了時点で、発見できた展示と新館の有無を記録する。

このフェーズでは網羅性よりも、初回来館者の認知負荷と自然な発見順を優先する。

### Phase 2: 競合の系統鑑賞

目安: 90〜120 分

`Docs/RIVAL_MUSEUM_RESEARCH.md` のラインナップをチェックリストにし、トップレベル 16 展示をすべて回る。2D 錯視ギャラリーは内部の 6 作品も個別に確認する。

各展示で次を実行する。

1. 接近時の見え方と、操作案内が現れる距離を確認する。
2. 金色マーカーを探し、通常視点と `E` スナップ後の見え方を比較する。
3. ヒントなしで 10 秒以上観察し、「何がどう見えたか」を自由記述する。
4. `H` でヒントを開閉し、観察前後で理解がどう変わったかを記録する。
5. 操作可能な 6 展示では、クリック、`F`、ホイールの該当操作をすべて試す。
6. 操作前、錯視成立時、種明かし／答え合わせ後のうち、結論に必要な画面を保存する。
7. 展示から離れ、次の展示へ戻る流れに摩擦がないか確認する。

「FABLE ORIGINALS」の 5 展示は、既知作品の再現とは別枠で次も確認する。

- 一文で体験を説明できるか。
- 見る位置、操作、種明かしが作品固有の驚きに結びついているか。
- 実装規模ではなく、来館者が知覚できる独自性があるか。
- 写真・短い動画・口コミで他者へ伝えやすいか。

### Phase 3: 自館の同条件鑑賞

目安: 60〜90 分

自館を初回来館状態にし、競合と同じ評価観点で 10 展示をすべて確認する。

1. タイトル、チュートリアル、最初の展示までの時間を測る。
2. 自由探索で展示の発見性、ゾーン表示、マップ、フォーカス距離を確認する。
3. 各展示で「観察 → 操作 → ヒント → 答え合わせ → リセット → 探索へ戻る」を実施する。
4. 共通作品とオリジナル作品を区別して記録する。
5. 自館にだけある機能（マップ、進捗、直接リンク、モバイル対応、設定など）は、競合にないという事実と、来館価値への影響を分けて評価する。

### Phase 4: 対応展示の直接比較

目安: 45〜60 分

作品数の違いを補うため、次の対応関係で短い比較タスクを行う。

| 比較テーマ | 競合 | 自館 | 確認する差 |
| --- | --- | --- | --- |
| 空間錯視 | エイムズの部屋 | エイムズの部屋 | 固定視点、種明かし、立体感 |
| 調整実験 | ミュラー・リヤー調整実験 | ミュラー・リヤー錯視 | 調整の分かりやすさ、数値フィードバック |
| 明るさ・色 | 色の恒常性の部屋、チェッカーシャドー | チェッカーシャドウ、色彩残響回廊 | 照明／文脈／順応の体験差 |
| 2D 古典錯視 | 2D 錯視ギャラリー | 該当する個別展示 | 一覧性と一作品の深さ |
| オリジナル作品 | FABLE ORIGINALS 5 展示、二つの真実 | 視差の花、色彩残響回廊 | 独自性、成立の明確さ、共有性 |
| 館内誘導 | 金色マーカー、増築棟入口 | フォーカス表示、ゾーン、マップ | 自由探索と迷いにくさ |

同じタスクを両館で行い、完了時間、誤操作回数、ヒントの必要性、錯視が成立したかを記録する。数値は少人数の操作計測として扱い、一般ユーザー全体の統計とは主張しない。

### Phase 5: ソースレベルの裏取り

目安: 45〜60 分

体験ログを固定した後で、観察結果の原因をソースから確認する。

競合では、利用可能なソース、ソースマップ、実行時状態から次を確認する。

- 展示とビュースポットの位置・向き・到達経路
- 接近判定、視点スナップ、操作キー、操作可能距離
- ヒント、答え合わせ、照明、ホイール調整の状態遷移
- 新館入口と展示の配置
- 読み込み単位、重いアセット、描画上の負荷要因

自館では主に次を確認する。

- `src/exhibits/exhibitCatalog.ts`: 展示構成、位置、距離、操作種別
- `src/scene/focus.ts` と `src/scene/player/`: 発見・接近・移動条件
- `src/ui/`: チュートリアル、ヒント、マップ、進捗、操作案内
- `src/state/useMuseumStore.ts`: 体験状態と復帰動作

ソース記録には必ず、対応する観察 ID と「この実装が体験へどう現れたか」を記載する。ソースで存在を確認しただけの機能は、来館者が発見・利用できた機能として加点しない。

### Phase 6: 評価とレポート作成

目安: 90〜120 分

各館を 5 段階で評価し、重み付きスコアは全体傾向の把握にだけ使う。

| 評価軸 | 重み | 5 点の目安 |
| --- | ---: | --- |
| 錯視の成立と視覚的インパクト | 15 | ヒントなしでも明確に成立し、記憶に残る |
| 展示の幅と独自性 | 12 | 原理・形式が多様で、固有の来館理由がある |
| 操作性とフィードバック | 12 | 入力と変化が即座に理解でき、試行を続けたくなる |
| 導入・館内ナビゲーション | 12 | 初回でも迷わず全体像と次の行動が分かる |
| 空間演出・ブランド一貫性 | 10 | 建築、照明、文言が一つの体験として機能する |
| 学習・種明かし | 10 | 驚きの後に原理を理解し、再観察できる |
| 仕上がり・安定性 | 8 | 破綻や待ち時間が体験を中断しない |
| アクセシビリティ | 7 | 入力、可読性、色、動きへの配慮がある |
| 再訪・共有性 | 8 | 再体験や他者への共有を促す仕掛けがある |
| 展示密度と滞在価値 | 6 | 数と深さが適切で、単調な繰り返しがない |
| **合計** | **100** |  |

点数の根拠には最低 1 件の観察 ID を付ける。重要な差異は、次の書式でまとめる。

```text
比較結果 ID:
観察事実:
体験への影響:
判断理由:
証拠 ID:
ソース裏付け（ある場合）:
確信度: 高 / 中 / 低
```

## 7. 最終レポートの構成

`REPORT.md` は次の順にする。

1. エグゼクティブサマリー
2. 調査条件と制約
3. 両館の来館体験フロー
4. 評価軸別の比較
5. 共通展示の直接比較
6. オリジナル展示の競争力
7. 自館の優位点
8. 自館の主要ギャップ
9. 集客・満足度へつながる改善機会
10. 追加検証が必要な仮説
11. 証拠一覧とソース確認記録

改善機会は、少なくとも次の 3 要素で優先順位を付ける。

- 来館体験への影響: 高／中／低
- 競合との差別化への寄与: 高／中／低
- 証拠の確信度: 高／中／低

実装工数はこの調査だけで断定せず、後続の改修計画でコード調査と見積もりを行う。

## 8. 完了条件

次をすべて満たした時点で調査完了とする。

- 競合のトップレベル 16 展示と、2D ギャラリー内 6 作品を確認した。
- 競合の操作可能な 6 展示で、用意された操作と変化を確認した。
- 競合の新館入口と「FABLE ORIGINALS」5 展示を確認した。
- 自館の 10 展示で、観察、操作、ヒント、答え合わせ、復帰を確認した。
- 両館を同一条件で最低 1 回ずつ通し鑑賞し、競合は初見・系統の 2 パスを行った。
- すべての主要な比較結果に、判断理由と画面または行動ログの証拠がある。
- ソース由来の結論には、対応する実体験の観察 ID がある。
- 自館の優位点と不足点の両方を記載した。
- 未確認事項、再現できなかった現象、調査者 1 名による限界を明記した。

## 9. 想定リスクと対処

| リスク | 対処 |
| --- | --- |
| localhost に接続できない | サーバー状態とポートを確認し、権限昇格した Chrome で再試行する |
| Pointer Lock で記録操作が難しい | `Esc` でカーソルを戻し、位置と状態をログしてから再開する |
| 錯視が成立しない | 視点、距離、画面サイズ、輝度、モーション設定を記録し、ビュースポットから再試行する |
| 展示を見落とす | 初見パス後に展示チェックリストとソース位置情報で系統パスを行う |
| スクリーンショットだけで動きが伝わらない | 前後画像と時系列メモを組み合わせ、必要なら短い画面収録を追加する |
| 既存画像の条件が不明 | 予備資料に留め、主要場面を条件固定後に再撮影する |
| 調査者の主観に偏る | 観察と解釈を分離し、確信度を付け、重要仮説は後日 3〜5 名のユーザーテスト候補とする |

## 10. 所要時間の目安

準備からレポート草稿まで約 6〜8 時間を見込む。体験中に再現しにくい錯視や不具合が見つかった場合は、再現確認を別枠にし、未完のまま評価点を断定しない。
