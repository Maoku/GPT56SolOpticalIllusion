## 1. 結論

現行 PARALLAX 2.0 は、企画上は「3D 空間自体を錯視の入力にする」と定義されているが、実装上は次の状態に留まっている。

1. 展示の中心は依然として HUD、ボタン、説明文であり、鑑賞中の視界と操作を遮る。
2. 3D 展示の成立条件より先に、状態切替、結果記録、パスポートなど周辺機能が実装されている。
3. 「状態が変わった」という UI 上の表示と、実際の 3D 表現の変化が結びついていない展示がある。
4. 自動テストは UI の状態遷移を主に検証し、錯視が視覚的に成立しているかを検証していない。
5. 実在の美術館における視線誘導、展示と解説の距離、滞留、順路の調査が、実装判断へ十分に反映されていない。

したがって、次の機能追加へ進むのではなく、PARALLAX 2.0 を「グレーボックス段階の展示プロトタイプ」として再評価する。最優先は UI の完成度ではなく、説明なしでも 3D 空間上で錯視が成立し、歩く行為だけで変化を発見できる状態を作ることである。

## 2. 課題の構造

### 2.1 最上位の体験課題

| 課題 | 現状 | 来館者への影響 | 根本原因 |
| --- | --- | --- | --- |
| 鑑賞より説明が前に出る | 大型 HUD、モーダルのヒント、状態切替、記録、原理表示が常時前景にある | 作品を見る前に UI を読むことになり、テンポと没入が失われる | 「迷わせないこと」を UI の説明量で解決している |
| 空間展示なのにボタン操作が主役 | マウス視点操作中に HUD のボタンを押す必要がある | Pointer Lock とカーソル操作が競合し、身体的な鑑賞が中断される | 展示固有の行為が共通 HUD の状態遷移へ置き換えられている |
| 3D 空間に展示本体がない | CLASSICS LAB は静的な簡略図で、実際の展示は全画面表示へ入らないと見えない | 美術館を歩く意味が弱く、3D 空間がメニュー画面になる | 1.0 の全画面展示をそのまま深掘り画面として残した |
| 展示の意図が伝わらない | SIGNATURE HALL は展示名と説明を読んでも、変化の境界や観察対象が明瞭でない | オリジナル作品が来館理由にならない | 一文コピーと UI はあるが、造形、視線、動き、背景のコントラストが未調整 |

### 2.2 操作・フォーカス課題

空間展示のフォーカス判定は展示中心座標までの距離を使う。一方、来館者が立つべき鑑賞点は展示中心から離れている。

| 展示 | 展示中心から鑑賞点まで | 現在の操作距離 | 結果 |
| --- | ---: | ---: | --- |
| チェッカーシャドウ | 5.4 m | 4.8 m | 鑑賞点ではフォーカス範囲外 |
| エイムズの部屋 | 5.5 m | 5.2 m | 鑑賞点ではフォーカス範囲外 |
| 視差の花 | 6.2 m | 5.2 m | 鑑賞点ではフォーカス範囲外 |
| 色彩残響回廊 | 5.5 m | 4.8 m | 鑑賞点ではフォーカス範囲外 |
| 折り畳まれた回廊 | 6.0 m | 5.2 m | 鑑賞点ではフォーカス範囲外 |
| 逆視差の窓 | 5.6 m | 5.2 m | 鑑賞点ではフォーカス範囲外 |

このため「mint 色の鑑賞点に立つ」と「操作する／ヒントの UI を出す」が両立しない。単純に操作距離を広げると隣接展示の誤フォーカスが増えるため、展示中心ではなく鑑賞点と参加領域を使う設計へ変更する必要がある。

### 2.3 個別展示の成立課題

#### 逆視差の窓

- 通常設定では奥のレイヤー位置がカメラ X 座標だけで決まり、`spatialStep` を参照しない。
- 「連続して歩く」と「二状態を静止比較」を切り替えても、通常モーション設定では HUD の文言しか変わらない。
- 窓の奥に奥行きを示す床、柱、地平線などが少なく、どの方向へ動いたかを比較しにくい。

#### エイムズの部屋

- 2 体の人物モデルに `1.35` と `0.58` の異なる scale が設定されている。
- 「同じ身長が違って見える」のではなく、最初から物理寸法の違う人物を表示している。
- 展示床と館内床がほぼ同じ高さにあり、面の干渉が起きやすい。
- 構造開示は床と天井を少し回転するだけで、横へ回り込んで部屋の歪みを発見する体験になっていない。

#### チェッカーシャドウ

- チェッカー面の各 mesh に `receiveShadow` がない。
- spotlight の target が、確実に円柱と盤面へ向く明示的な Three.js オブジェクトとして管理されていない。
- 館内の環境光と大きな白色面が局所照明の差を弱めている。
- 現行鑑賞点では円柱が盤面を大きく遮り、A/B と影の関係が読み取りにくい。
- UI 上の三状態を切り替えても、代表画面で明瞭な before / after が得られない。

#### CLASSICS LAB

- 6 展示すべてが `presentation: "lab"` で、操作時に全画面の `ExhibitExperience` へ遷移する。
- 館内の `Miniature` は錯視の完全な縮小版ではなく、展示によっては同じ簡略パターンを流用している。
- ネッカーキューブ、運動誘発盲を含め、3D 空間上の展示を眺めただけでは原理を体験できない。

#### PARALLAX SIGNATURE HALL

- 視差の花は成立点と分解状態を持つが、大型 HUD が作品の一部を覆う。
- 色彩残響回廊は奥へ歩く回廊ではなく、横並びの三つの区画に見える。
- 折り畳まれた回廊は成立前から入れ子状の回廊に見え、崩れた状態との反転が弱い。
- 逆視差の窓は比較基準となる奥行き手がかりが不足している。
- 4 展示とも「どこを見るか」「何が反転したか」を造形だけで伝えられていない。

### 2.4 検証方法の課題

- V2 空間展示の E2E は `?scene=off` で実行され、HUD のボタン、記録状態、テキストだけを確認する。
- `VIEW FOUND` は、視差の花と折り畳まれた回廊以外では、視覚的成立ではなく鑑賞点までの物理距離を px 表示へ変換している。
- UI が `0 px` と表示しても、影、人物の見え方、逆視差が成立している保証はない。
- `Docs/PERCEPTUAL_VALIDATION.md` は 2 展示用の手順のみで、実施結果が記録されていない。

既存の `TRANSFORMATION_PLAN.md` が定めた「4/5 人で成立」の判断ゲートは、実装継続前に実施されるべきだった。今後はこのゲートを必須に戻す。

## 3. 改修原則

### 3.1 作品を先、説明を後にする

1. 遠景から作品または変化の一部が見える。
2. 近づくと床、光、造形により立ち位置が分かる。
3. 歩く、覗く、止まる、照明器具を触る行為で錯視が変化する。
4. 来館者が変化を見た後に、短い問いと種明かしを選べる。
5. 数値、原理、パスポートは体験後の補助として提供する。

通常鑑賞中にモーダルを開くことを前提にしない。

### 3.2 PARALLAX 1.0 のコードではなく強みを融合する

維持対象は全画面展示や操作ウィンドウではなく、次の体験価値である。

| 1.0 の強み | 2.0 での融合方法 |
| --- | --- |
| 自分で値を変えられる | 歩行、照明、視点、展示台の実物操作へ置き換える |
| 答え合わせができる | 壁や床が開く、照明が中立化する、横から構造が見える演出にする |
| 数値で確かめられる | 鑑賞後に任意で開く小さな結果カードへ移す |
| 操作が一貫している | キーボード・タッチ代替と離脱操作に限定して一貫させる |
| ヒントが段階的 | 館内サイン、短い非遮蔽ヒント、任意の詳細解説の三段階にする |
| 進捗とアクセシビリティ | 背景で記録し、鑑賞の主画面を占有しない |

### 3.3 展示ごとに成立契約を持つ

全展示に同じ `spatialStep` と同じ HUD を当てはめない。展示ごとに次を定義する。

- 来館者の主行為
- 観察対象
- 成立前の見え方
- 成立後の見え方
- 種明かしの方法
- reduced-motion／キーボード／タッチの代替
- 3D 表現が変化したことを検証する指標

UI の状態名ではなく、シーン側の変化を正本とする。

## 4. 優先順位

| 優先 | 対象 | 理由 |
| --- | --- | --- |
| P0 | 鑑賞点で反応しない問題 | 全空間展示の入口を壊している |
| P0 | チェッカーシャドウ、エイムズ、逆視差 | 展示の主張と実際の描画が一致していない |
| P0 | 大型 HUD とモーダル中心の操作 | 鑑賞行為そのものを妨げている |
| P1 | SIGNATURE HALL 4 展示の成立と明瞭化 | PARALLAX 2.0 の来館理由に直結する |
| P1 | CLASSICS LAB の館内ライブ展示化 | 3D 美術館を単なるメニューにしないために必要 |
| P1 | 実在美術館調査に基づく順路・視線・解説配置 | 局所修正の寄せ集めを防ぐ |
| P2 | パスポート、共有、詳細な数値記録 | 展示が成立した後に価値を持つ |

P0 の成立確認が終わるまで、新展示、共有機能、パスポート演出の追加を止める。

## 5. 実施計画

### Phase 0: 現状固定と実在美術館調査

机上調査成果（2026-07-24）:

- National Gallery、Exploratorium、teamLab Borderless、Camera Obscura & World of Illusions の4館を、公式資料に基づき比較した。
- 来館ジャーニー、平面スケッチ、解説配置ルール、7つの展示原則、現行館内との差分を `Docs/research/real-museums/2026-07-24/` に記録した。
- 現地の実時間、実距離、混雑時滞留、作品別の同時鑑賞人数は未計測であり、後続の現地調査または初見ユーザーテストで補完する。

#### 目的

UI の好みではなく、美術館としての鑑賞行動を判断基準にする。

#### 調査対象

実在館から最低 3 館を選び、次の異なる形式を含める。

- 美術作品を静かに鑑賞する館
- 科学・知覚を体験操作する館
- 空間没入または錯視を主題にする館

現地調査が難しい館は、公式フロアマップ、公式展示写真、公式バーチャルツアー、アクセシビリティ案内で補完する。競合デジタル館の調査だけで代替しない。

#### 観察項目

- 入口から最初の展示が見えるまでの時間と視線
- 遠景のランドマーク、展示室の閾、次室の予告
- 作品、キャプション、長文解説の距離と読む順序
- 立ち止まる場所、追い越し、回遊、行き止まり
- 操作説明を読む前に触れるか、見れば分かるか
- 一作品の前で同時に滞在できる人数
- 種明かしや解説が作品を遮らない方法
- 子ども、車椅子、色覚、聴覚、モーション配慮
- 退出時の振り返り、記録、ショップ相当の余韻

#### 成果物

- 来館ジャーニーマップ
- 館内の視線と順路を示す平面スケッチ
- 「作品→短い問い→詳細解説」の配置ルール
- PARALLAX 2.0 に採用する 5〜7 個の展示原則
- 現行館内との差分表

#### 終了条件

- 各設計原則に、少なくとも一つの実在館での観察根拠がある。
- 入口、SIGNATURE HALL、CLASSICS LAB、SCALE + LIGHT の来館フローが一枚で説明できる。
- 「何を UI に出さず、空間で伝えるか」が合意されている。

### Phase 1: 非遮蔽インタラクション基盤

#### 1. 鑑賞点と参加領域

`ExhibitDefinition` に展示中心とは別の参加領域を定義する。

```ts
type InteractionAnchor = {
  id: string
  position: [number, number, number]
  radius: number
  target?: [number, number, number]
  activation: 'automatic' | 'confirm'
}
```

- 空間展示は `viewSpots` または専用 `interactionAnchors` をフォーカス判定に使う。
- 鑑賞点へ入った時点で、展示はその場で自動的にアクティブになる。
- 退出時は半径にヒステリシスを持たせ、境界で表示が点滅しないようにする。
- 近接展示が重なる場合だけ視線方向と遮蔽レイキャストで一つへ絞る。
- 「操作する」ボタンは空間展示の主操作から外し、キーボード・タッチの代替開始に限定する。

#### 2. HUD

通常鑑賞時は次だけを表示する。

- 展示名
- 10〜20 文字の問い
- 必要な場合だけ一つの行為指示
- 終了／支援を開く操作

状態切替、結果記録、原理、メーターを一度に並べない。大型左パネルを廃止し、作品の画面領域と重ならない下端または端部の小型表示へ変更する。

#### 3. ヒント

- 第 1 段階: 床、壁、光で示す。
- 第 2 段階: Pointer Lock を解除しない一行ヒントを表示する。
- 第 3 段階: 来館者が明示的に詳細を求めた場合だけ、非モーダルのサイド解説を開く。
- 暗い backdrop と全画面停止は、設定、アクセシビリティ、長文の詳細解説だけに限定する。

#### 終了条件

- 6 空間展示すべてで鑑賞点に立つと確実に反応する。
- マウス視点操作中に HTML ボタンを押さなくても、主体験を完了できる。
- 作品の主要領域を HUD が覆わない。
- キーボードのみ、タッチのみでも同じ状態へ到達できる。

### Phase 2: P0 展示の知覚成立を修正

#### 2.1 逆視差の窓

1. 「通常視差」と「逆視差」を別の明示的なシーン状態として実装する。
2. カメラ X、窓枠、奥のレイヤーの関係を純粋関数へ分離する。
3. 通常視差では奥の部屋を静止し、逆視差では投影上の移動方向が反転するゲインを適用する。
4. 床グリッド、柱、奥壁、前景枠を追加し、動きの比較基準を作る。
5. 連続歩行を主体験にし、reduced-motion では左右二視点の静止比較を自動提示する。
6. UI の状態切替は、必ずシーンのモード変更または視点変更を伴う。

合格条件:

- 左右移動時、通常状態と逆視差状態で奥レイヤーの画面上移動方向が反転する。
- 静止画二枚でも違いが説明できる。
- 5 人中 4 人がヒントなしで「奥が不自然な方向へ動いた」と説明できる。

#### 2.2 エイムズの部屋

1. 2 体の Figure は同じ geometry、同じ scale、同じ実寸にする。
2. 固定視点から長方形に見える台形の床、天井、奥壁、側壁を同一座標系で設計する。
3. 館内床と展示床を分離し、開口部または十分な高さ差で面干渉をなくす。
4. 固定鑑賞点では外部形状をマスクし、人物と部屋の投影だけを見せる。
5. 種明かしは床を少し回すのではなく、横へ歩ける回廊または第 2 鑑賞点で実形状を見せる。
6. 「状態切替」ではなく「固定視点から見る／横へ回り込む」を実際の移動として設計する。

合格条件:

- ソース上も実測上も 2 体の人物寸法が同一である。
- 固定視点では人物の見かけの大きさに明瞭な差がある。
- 横視点では床と壁の歪みを一目で確認できる。
- 代表カメラで床のちらつき、欠け、面干渉がない。
- 5 人中 4 人が「同じ人物が部屋によって違う大きさに見える」と説明できる。

#### 2.3 チェッカーシャドウ

1. 盤面を `receiveShadow` にし、円柱を `castShadow` にする。
2. light target を明示的な `Object3D` として盤面上へ向ける。
3. A は影の外、B は影の内に置き、両セルの物理色を同一にする。
4. 円柱、影、A/B が同時に見える鑑賞点へカメラ構図を変更する。
5. 局所照明を環境光から分離し、影の明暗差を保つ。
6. 端末や品質設定による shadow map の不成立を避けるため、必要ならプロシージャルな影デカールまたはシェーダーマスクを正本にする。
7. 種明かしでは影と周囲文脈を外し、A/B を色帯で直接接続する。

合格条件:

- 初期状態で円柱から連続する影の輪郭が見える。
- B は影の中、A は影の外にある。
- 中立状態で A/B が同じ色であることを視覚的・数値的に確認できる。
- 高品質・低品質の両方で錯視の主効果を失わない。
- 5 人中 4 人がヒントなしで A/B を異なる明るさとして報告する。

### Phase 3: SIGNATURE HALL の再構成

4 展示を同時に高詳細化しない。各展示を無彩色グレーボックスへ戻し、成立前／成立後が十分に違うことを確認してから素材と照明を追加する。

#### 視差の花

- 入口では三層が明らかに分離して見える。
- mint の一点だけで、認識可能な一輪へ重なる。
- 状態切替で分解するのではなく、横へ数歩動くと自然に分解して見える。
- 成立点から作品全体が HUD に隠れない。

#### 色彩残響回廊

- 横並びの三面ではなく、順応室→移行帯→結果室を奥行き方向に歩く。
- 注視対象を建築の焦点として配置する。
- 経過時間は大型タイマーで説明せず、光と音の変化で伝える。
- 注視が難しい来館者には短縮、静止比較、スキップを用意する。

#### 折り畳まれた回廊

- 壁片は横から見ると分断され、成立点でだけ直線回廊になる。
- 成立状態を初期配置として固定せず、入口から成立点まで変化が読める。
- 側路から実形状を見られる種明かしを作る。

#### 逆視差の窓

- Phase 2 の知覚成立後、SIGNATURE HALL の背景、導線、他展示との距離を調整する。
- 他の alignment 展示と連続しないよう、身体行為を「左右歩行」に明確化する。

#### SIGNATURE HALL 全体の終了条件

- 入口から 4 展示のうち少なくとも 1 点の異変が見える。
- 各展示を 15 秒以内の一文で説明できる。
- 4 展示の主行為が重複しない。
- 各展示で 5 人中 4 人がヒントなしに意図した変化を報告する。

### Phase 4: CLASSICS LAB のライブ展示化

#### 方針

全画面展示を廃止すること自体が目的ではない。まず、廊下を歩くだけで 6 作品の初期錯視を比較できる状態にする。深掘り画面は、実験値や詳細解説を求める来館者向けの任意機能へ格下げする。

#### 展示別の最低要件

| 展示 | 3D 空間上で常時見えるもの | 直接操作 |
| --- | --- | --- |
| ミュラー・リヤー | 同じ長さの二線と異なる矢羽 | 展示台で片方の線を調整 |
| ポンゾ | 収束線と等長の二線 | 奥行き位置を展示台で変更 |
| エビングハウス | 左右両方の中央円と周囲円 | 中央円または周囲円を変更 |
| カフェウォール | 効果が成立する十分な行数のタイル | 行ずれを変更 |
| ネッカーキューブ | 実際の線画キューブ | 手前解釈の色手がかりを切替 |
| 運動誘発盲 | 注視点、静止点、動く背景 | 動作開始／停止と静止代替 |

#### 実装方針

- 2D 錯視は CanvasTexture、SVG texture、限定的な R3F mesh を使い、展示枠の中へ直接描画する。
- アニメーションは視界内かつ近距離の展示だけ更新する。
- 操作卓は一展示一操作を基本にし、複数 slider を常時出さない。
- 詳細実験を開く場合も、館内を残したサイドドロワーまたは局所拡大を優先する。
- ヒントを開かなくても、展示枠だけで主効果を観察できるようにする。

#### 終了条件

- 6 展示すべての主効果が、ウィンドウを開かず館内で見える。
- 入口から複数展示の違いを比較できる。
- 各展示の主操作を一つの展示台または一つのキーで開始できる。
- 全画面深掘りを使わなくても「体験済み」と記録できる。

### Phase 5: 説明・結果・パスポートの再配置

P0/P1 の展示成立後に実施する。

- 体験前は問いだけを出す。
- 体験中は行為指示だけを出す。
- 体験後に、種明かし、数値、結果記録を選べる。
- 結果記録は自動または一操作とし、鑑賞中に記録ボタンを常設しない。
- パスポートは館内出口、休憩地点、タイトルの「続きから」で開ける。
- 詳細解説を読まなくても回遊と体験完了ができる。

### Phase 6: 視覚検証と公開判定

#### 自動検証

E2E は、目的の異なる次の二層へ明確に分離する。`scene=off` の結果を、3D 空間展示の合格根拠として扱わない。

| E2E 層 | 実行条件 | 検証対象 | 検証対象外 |
| --- | --- | --- | --- |
| HTML UI E2E | `?scene=off` | オンボーディング、マップ、設定、ヒント、パスポート、フォーム操作、キーボード操作、状態保存、アクセシビリティ | 3D 描画、移動、フォーカス、影、照明、錯視成立 |
| 3D 空間 E2E | scene 有効 | 入館、移動、展示への接近、鑑賞点フォーカス、カメラ移動、空間状態変化、展示離脱、代表視点の描画 | 詳細な知覚成立の最終判定 |

- ファイルまたは Playwright project を分け、テスト名とレポート上でも二層を識別できるようにする。
- CI では HTML UI E2E と 3D 空間 E2E を別ジョブまたは別コマンドで実行し、どちらが失敗したかを明確にする。
- HTML UI E2E は高速・並列実行を優先し、WebGL／GPU に依存させない。
- 3D 空間 E2E は WebGL を有効にし、固定 viewport、固定カメラ、決定的な展示状態で実行する。
- 3D 空間 E2E の失敗を `scene=off` へ切り替えて回避しない。環境起因の場合は失敗理由を分離し、検証環境を修正する。
- 3D 空間 E2E は scene の存在を確認するだけでなく、状態変更前後の 3D パラメーターまたは代表スクリーンショットが変化したことを確認する。
- 詳細な錯視成立は、固定カメラの視覚回帰と人による知覚検証を併用して判断する。

- 6 空間展示の鑑賞点がフォーカス対象になる単体テスト
- interaction anchor のヒステリシスと重複選択テスト
- 逆視差の camera X→layer X の方向テスト
- Ames Room の 2 体が同一寸法であることのテスト
- shadow state と light state の scene property テスト
- 展示ごとの状態変更が 3D パラメーターを変えるテスト
- 固定カメラによる成立前／成立後のスクリーンショット比較
- HUD と作品の主要画面領域が重ならない代表 viewport テスト

`scene=off` の E2E は HTML UI と状態管理の品質ゲートとして残す。一方、空間展示のリリースには scene 有効 E2E の成功を必須とし、片方の成功で他方を代替しない。

#### 手動・知覚検証

各空間展示で制作に参加していない 5 人以上を対象に実施する。

1. ヒントなしで観察する。
2. 来館者が自力で主行為を開始できるか確認する。
3. 何が変わったか自由回答を得る。
4. 一行ヒント後に再試行する。
5. 種明かし後、原理を一文で説明してもらう。

記録項目:

- 初回反転までの時間
- UI ボタンを探した回数
- ヒント利用の有無
- 意図した変化の自由回答
- 作品を一文で再説明できたか
- 作品の視界を UI が遮ったか
- 気分不良、読みにくさ、操作困難

#### リリースゲート

- P0 の 3 展示がすべて成立条件を満たす。
- SIGNATURE HALL の各展示が 4/5 人以上で意図した変化を伝えられる。
- 12 展示の主効果を、全画面ウィンドウなしで館内から確認できる。
- 6 空間展示をマウス視点中のボタンクリックなしで体験できる。
- HTML UI E2E と scene 有効の 3D 空間 E2E が、それぞれ独立して全件成功する。
- ヒントを開かなくても回遊でき、開いた場合も作品の主要領域を遮らない。
- デスクトップ、375 px モバイル、低品質、reduced-motion で主要フローが成立する。
- V1 を既定に残す場合は、V2 の合格まで切替を行わない。

## 7. 推奨する実施単位

改修を大きな一括 PR にしない。次の順で、各段階を独立してレビュー可能にする。

1. 実在美術館調査と展示原則
2. interaction anchor と全鑑賞点のフォーカス修正
3. 非遮蔽 HUD／ヒントの体験プロトタイプ
4. チェッカーシャドウ成立修正
5. エイムズの部屋成立修正
6. 逆視差の窓成立修正
7. SIGNATURE HALL グレーボックス再検証
8. CLASSICS LAB ライブ展示化
9. 説明、結果、パスポートの再統合
10. 5 人知覚テスト、視覚回帰、性能確認、公開判断

各展示 PR は「見た目の改善」ではなく、成立前／成立後の画像、ヒントなしの観察結果、代替操作を添付して完了とする。

## 8. 最初の着手判断

直ちに実装へ入る場合でも、最初の対象は個別の装飾ではなく次の二つとする。

1. 全空間展示の鑑賞点を参加領域として認識させる。
2. チェッカーシャドウを、説明なしで影が見える最小グレーボックスへ戻して成立させる。

この二つで「立つべき場所に立てば、UI を操作しなくても作品が働く」という PARALLAX 2.0 の基本契約を先に証明する。その後、同じ契約をエイムズ、逆視差、SIGNATURE HALL、CLASSICS LAB へ展開する。
