# PARALLAX 競合調査後 改修計画

> **位置づけ変更:** 本書は既存構造を守る漸進案として残す。美術館全体を対象にした現行の推奨案は [PARALLAX 2.0 ドラスティック改修計画](./TRANSFORMATION_PLAN.md) を参照。

根拠: [競合美術館 調査レポート](./REPORT.md)  
調査対象実装: `e1538819168de5320f39bbf0794ef37746bc1d5f`

## 1. 改修の目的

PARALLAX がすでに持つ「迷いにくさ、共通操作、段階的な学習、進捗、アクセシビリティ」を維持したまま、競合との差が大きかった次の3点を補う。

1. 館内の位置と建築が錯視の成立条件になる象徴展示
2. 初見で行きたくなるオリジナル展示の目的地
3. 一文と before / after で持ち帰れる体験結果

この改修の成功は、展示数の増加ではなく、来館者が「PARALLAX で何を見たか」を一場面・一文で説明できる状態で判定する。

## 2. 方針決定

### 2.1 10展示を維持し、#09「視差の花」を空間展示へ昇格する

11点目を追加せず、既存オリジナルの #09 を `PARALLAX SIGNATURE` の中心作品へ作り替える。現在の花弁、位相、視差という固有性を残しつつ、スライダー中心の全画面展示から、来館者が館内を一歩動くことで像が成立・崩壊する3Dインスタレーションへ変更する。

想定する一文は次のとおり。

> 散らばっていた三層の花弁が、正しい視点では一輪の花に揃う。

既存の展示番号、直接リンク、進捗、ヒント、答え合わせ、リセットは維持する。これにより、競合の模倣ではなく、館名 `PARALLAX` と既存オリジナルを一つの象徴体験へ接続する。

### 2.2 後方ゾーンを `PARALLAX SIGNATURE` として目的地化する

現在の後方「空間と残像」ゾーンへの境界を、サイン、照明、床の視点マーカーで明確にする。#09 と #10 をオリジナル展示群として編集し、マップにも名称を反映する。

自由探索は既定のままとし、強制ルートや自動テレポートは導入しない。手動で成立位置を探せない場合の補助としてのみ「鑑賞点へ移動」操作を用意する。

### 2.3 結果カードは #09 と #01 から始める

共有基盤を全展示へ一括展開せず、次の2種類で縦切りする。

- #09 視差の花: 成立位置 / 位置ずれの before / after と象徴的な一文
- #01 ミュラー・リヤー: 調整値を実長との差の百分率へ変換した個人結果

保存用カードは 1200 × 630 px を基本とし、Web Share API、画像保存、リンクコピーの順に利用可能な手段を提示する。個人情報や自動投稿は扱わない。

## 4. 体験仕様

### 4.1 #09「視差の花」の体験フロー

1. 後方ゾーン入口から、分離した三層の花弁が見える。
2. 展示へ近づくと、現在と同じ展示名、問い、ヒント操作が出る。
3. `操作する` を選んでも3D館内は隠さず、空間展示HUDへ切り替える。
4. 来館者が床の視点マーカー付近へ動くと、投影上の花弁が一輪へ収束する。
5. 成立範囲へ入ると、色だけに依存しない輪郭と短いフィードバックを出す。
6. `答え合わせ` では、三層の実配置、基準視点、投影が揃う理由を段階表示する。
7. `結果を見る` から、成立 / 位置ずれのカードを表示する。
8. `リセット` で初期観察位置と未開示状態へ戻し、`終了` で探索へ復帰する。

成立判定は単純な距離だけでなく、カメラから投影した基準点の画面上誤差で行う。位置、向き、FOV、アスペクト比によるずれを同じ純粋関数で評価し、視覚テストにも再利用する。

### 4.2 入力とアクセシビリティ

- デスクトップ: 現行の移動 / 視点操作を継続する。
- タッチ: 現行スティックと右側ドラッグを継続する。
- キーボード / スイッチ相当: 「鑑賞点へ移動」で成立位置へ直接移れる。
- モーション軽減ON: カメラ補間を使わず即時移動し、成立 / 位置ずれを静止切替でも比較できる。
- 高コントラスト: 成立状態を色だけでなく輪郭、文言、アイコンで示す。
- ヒント: 来館者が明示的に開くまで答えを見せない現行契約を守る。

### 4.3 結果カード

共通カードは以下を持つ。

- 館名、展示番号、展示名
- 一文で説明できる結果
- before / after または個人値 / 物理値
- `もう一度試す`
- `画像を保存`
- 利用可能な場合の `共有`
- `リンクをコピー`

#09 の画像は任意のブラウザスクリーンショットに依存させず、展示と同じ投影データから決定的に描画する。#01 は現在の `px` 表示を残し、カード上では符号付き百分率も併記する。

## 5. 実装フェーズ

### Phase 0: 成立条件の固定とプロトタイプ

目的: 本実装の前に、#09 が「一歩で反転する」ことを確認する。

作業:

- 三層の花弁配置、基準カメラ、位置ずれカメラを手続き生成する。
- 投影誤差から `alignmentScore` を返す純粋関数を作る。
- 1200 × 734、1440 × 900、代表的なスマートフォン縦横で成立 / 非成立を比較する。
- 高品質 / 低品質、モーション軽減ONで確認する。
- 開発用の限定ルートまたはStory相当画面で、館内結合前に知覚テストを行う。

終了条件:

- 成立画像と0.8〜1.2m横へずれた画像を、未説明の観察者4/5以上が区別できる。
- 4/5以上がヒントなし90秒以内に成立位置を見つけられる、または床マーカーだけで到達できる。
- 一文説明が意図した「位置で花が揃う」と一致する。

判断ゲート:

- 条件未達なら館内統合へ進まず、花弁間隔、奥行き、照明、基準位置を調整する。
- 2回の調整でも未達なら、#09 の名称は維持したまま輪郭を花から `PARALLAX` シンボルへ単純化する。

### Phase 1: 空間展示の共通基盤

目的: 全画面パネルを前提にした現行展示基盤へ、3D館内を見たまま操作する表示形式を追加する。

作業:

- `ExhibitDefinition` に `presentation: 'panel' | 'spatial'` を追加する。
- 展示総数表示のハードコードを `exhibitCatalog.length` 由来へ統一する。
- `App` と `ExhibitExperience` をパネル展示 / 空間展示で分岐する。
- `PlayerController` に空間展示中の移動範囲、離脱、鑑賞点移動を追加する。
- 直接リンクで #09 を開いた場合に、入口ではなく安全な初期観察位置へカメラを配置する。
- 進捗の `unvisited → interacted → revealed` は変更せず、空間展示の成立または操作で `interacted` にする。
- ヒント、答え、リセット、終了を `SpatialExhibitHud` でも同じ位置・キーで提供する。

主な変更候補:

- `src/exhibits/exhibitCatalog.ts`
- `src/app/App.tsx`
- `src/app/bootstrap.ts`
- `src/state/useMuseumStore.ts`
- `src/scene/player/PlayerController.tsx`
- `src/exhibits/ExhibitExperience.tsx`
- `src/exhibits/interaction/types.ts`
- 新規 `src/exhibits/interaction/SpatialExhibitHud.tsx`
- 新規 `src/scene/exhibits/signatureAlignment.ts`

終了条件:

- #01〜#08、#10 の表示と操作は現状どおり。
- #09 はCanvasを隠さずに開始、回答、リセット、終了できる。
- `/?exhibit=parallax-bloom` から同じフローへ入れる。
- Pointer Lock、タッチ、ダイアログのフォーカス制御が競合しない。

### Phase 2: `PARALLAX SIGNATURE` 本実装

- 既存コリジョンへ入口、作品、鑑賞点の安全領域を反映する。
- 低品質では影、発光、花弁数を抑え、錯視の輪郭は維持する。

主な変更候補:

- 答え表示が錯視を壊すだけでなく、三層と基準視点の関係を説明する。

### Phase 3: 結果カードと再挑戦

目的: 体験の結果を、説明可能・保存可能・再訪可能にする。

作業:

- 展示モジュールから個人結果を渡す `ExhibitOutcome` 契約を追加する。
- `ResultCard` と決定的なカード画像レンダラーを追加する。
- #09 に成立 / 位置ずれのカードを追加する。

- Web Share API が使えない場合は画像保存とリンクコピーへフォールバックする。
- 結果値をURLへ含めるのは利用者が明示的に共有した場合だけにする。
- 結果カードを閉じても展示状態を保持する。

主な変更候補:

- `src/exhibits/interaction/types.ts`
- `src/exhibits/ExhibitExperience.tsx`
- `src/exhibits/mullerLyer/MullerLyerExhibit.tsx`

終了条件:

- 共有API非対応、共有キャンセル、画像保存失敗が展示体験を壊さない。
- カード単体で展示名、何が起きたか、個人結果を理解できる。
- `もう一度試す` が同じ展示の初期状態へ戻る。

### Phase 4: P1導線

P0の観察テスト合格後に着手する。

1. ロビーまたはマップに #01、#05、#09、#10 のミニプレビューを並べる。
2. プレビューから個別展示へ直接移れるようにし、「一覧でつまむ → 深く実験する」の二層構造を作る。
3. 結果カードとマップに、未体験作品から1点だけ「おすすめ次作品」を出す。
4. おすすめを閉じても自由探索へ戻れ、順路を強制しない。
5. 次の形式多様化候補として、#05 を館内照明の切替で成立する展示へ変える小規模プロトタイプを評価する。

## 10. 主なリスクと対策

| リスク                             | 対策                                                                        |
| ---------------------------------- | --------------------------------------------------------------------------- |
| 基準解像度以外で花が揃わない       | 世界座標距離ではなく投影誤差で判定し、FOV / アスペクト別の視覚fixtureを持つ |
| 成立位置への移動が難しい           | 床マーカー、輪郭フィードバック、任意の「鑑賞点へ移動」を段階的に出す        |
| カメラ移動で酔う                   | 自動移動を必須にせず、モーション軽減時は補間なしの切替にする                |
| 3D展示だけ共通操作から外れる       | `SpatialExhibitHud` でもヒント / 答え / リセット / 終了の位置とキーを守る   |
| 結果カード生成がブラウザ差で壊れる | DOMスクリーンショットではなく、同じ投影データからCanvasへ決定描画する       |
| 初期ロードと描画負荷が増える       | 外部アセットを避け、インスタンシング、遅延ロード、非アクティブ時停止を使う  |
| 入口演出が自由探索を損なう         | 推奨は視覚的な誘引に留め、強制順路や自動マップ表示を使わない                |
| 競合の表現模倣になる               | 花、視差、段階的な種明かし、定量フィードバックをPARALLAX固有の軸にする      |

## 11. P0 Definition of Done

- #09 が館内の位置によって成立し、1m前後の位置差で明確に崩れる。
- `PARALLAX SIGNATURE` が館内とマップの両方で発見できる。
- #09 のヒント、答え、リセット、終了、直接リンク、進捗が動く。
- #09 と #01 で一文と結果を持つカードを保存できる。
- モーション軽減、高 / 低品質、デスクトップ、タッチ、キーボードで主要フローが成立する。
- 既存10展示、マップ、進捗、設定、チュートリアルに回帰がない。
- 自動テスト、production build、圧縮後5MB予算を通過する。
- 小規模観察テストが定義した合格目安を満たす。
- P1へ進むか、#09を再調整するかの判断記録が残っている。
