## 1. エグゼクティブディシジョン

PARALLAX 2.0 は、現在の「3D美術館を歩き、10個の全画面実験へ入る」構造を廃止する。建築、来館者の位置、照明、移動そのものを錯視の入力にし、館内を次の構成へ再編する。

- **12展示**
- **6つの部屋型 / 空間型展示**
- **4つのPARALLAXオリジナル**
- **6つの古典錯視を比較できる実験ギャラリー**
- **来館結果を統合する知覚パスポート**

既存10展示のIDと学習内容は捨てない。#05、#08、#09、#10を空間体験へ全面改修し、新しい空間オリジナルを2点追加する。#01〜#04、#06、#07は一覧ギャラリーから深掘りできる二層構造へ再編集する。

この計画のゴールは、競合の展示数や黒 / 金の演出を追うことではない。競合が強い「驚き、空間、共有」に、PARALLAXが強い「操作、学習、定量結果、アクセシビリティ」を同じ展示内で重ね、比較調査と同じ評価軸で明確に上回ることにある。

## 2. 勝ち筋

### 2.1 競合との差を埋めるのではなく、評価軸を統合する

競合の強作は、来館理由と共有理由が同じ作品の中にある。一方、現行PARALLAXでは驚きと学習が別画面へ分かれている。

PARALLAX 2.0 の全アンカー展示は、次の5条件を必須契約とする。

1. **身体入力**: 歩く、覗く、止まる、照明を切り替えるなど、館内行動が結果を変える。
2. **明瞭な反転**: 数歩または一操作で、before / after が静止画でも区別できる。
3. **一文の物語**: 未体験者へ15秒で説明できる。
4. **段階的な種明かし**: ヒント、原理、物理値を必要な時だけ開ける。
5. **持ち帰れる結果**: 個人値、二状態比較、または短いリプレイを保存できる。

この5条件を満たさない新展示は、作品数を増やす目的では公開しない。

### 2.2 「完成させる場所」ではなく「再訪したくなるプロフィール」を作る

現在の進捗は10 / 10の完了を支えるが、完了後に残るのは件数だけである。PARALLAX 2.0では、各展示の結果を4軸へ編集した `PERCEPTION PASSPORT` を来館の最終成果にする。

- **PERSPECTIVE** — 遠近、視差、固定視点
- **CONTEXT** — 周囲の大きさ、線、影による補正
- **LIGHT** — 明るさ、色順応、照明文脈
- **MOTION** — 注視、運動、反転の安定性

これは視力検査や診断ではない。「今回の実験で、どの手がかりに強く影響されたか」を記録する娯楽・学習用プロフィールとして明記する。

### 2.3 美術館ブランドをHUDではなく建築へ移す

mint / magenta、問い、番号、ゾーンのブランドを、入口、照明、床、視点マーカー、展示の素材へ展開する。全画面展示に入るたびに館内が消える現状を改め、少なくとも6展示ではCanvasと建築を見たまま体験を完結させる。

## 3. PARALLAX 2.0 の館内構成

### A. ARRIVAL ATRIUM — 最初の60秒で約束を見せる

入館すると、#09 `PARALLAX BLOOM` の巨大な分解形が吹き抜け越しに見える。正面では完成せず、移動中の一瞬だけロゴ状の花へ揃う。入口で全体説明を読み切らなくても、「位置で世界が変わる館」だと理解できる構成にする。

タイトル画面の訴求は件数だけでなく、体験形式を明示する。

> 12の錯視。6つの部屋。あなたの目だけが作る結果。

現在の3段階モーダルチュートリアルは、入館直後の驚きを遮るため、初回45秒に分散する文脈プロンプトへ置き換える。設定画面から従来型の操作説明をいつでも再表示できるようにし、アクセシビリティは後退させない。

### B. PARALLAX SIGNATURE HALL — オリジナルのために来る場所

#### #09 PARALLAX BLOOM — 空間化

三層の花弁を異なる奥行きへ分解配置し、正しい位置だけで一輪へ揃える。現行の花弁数、位相、追従量は答え表示側の学習パラメーターとして残し、主入力はスライダーから身体移動へ変更する。

一文:

> ばらばらの三層が、一歩だけ一輪の花になる。

#### #10 CHROMATIC ECHO CORRIDOR — 回廊化

現在のSVG / スライダー展示を、実際に歩く三段階の回廊へ変える。

1. 色順応室
2. 無彩色の移行帯
3. 補色が現れる結果室

注視が難しい来館者向けに、自動時間短縮、静止比較、スキップを残す。

一文:

> 色の部屋を出た瞬間、色のない壁に反対色が現れる。

#### 新オリジナル2点

6案以上を紙 / Three.jsグレーボックスで作り、次の候補から知覚テスト上位2点だけを採用する。

- **FOLDED CORRIDOR**: 分断された門と壁が、一つの視点だけで30mの直線回廊に見える。
- **COUNTERPARALLAX WINDOW**: 左へ歩くと、窓の奥の部屋が通常と逆方向へずれて見える。
- **BORROWED SHADOW**: 物体を動かしても影だけが別の規則で残り、照明切替で偽の構造が分かる。
- **TWIN HORIZONS**: 同じ高さの二つの地平線が、歩く位置で上下を入れ替える。

採用条件:

- 競合の「消える林」「嘘つきの鏡」「動きが生む幽霊」と体験説明が重ならない。
- 一操作または1.5m以内の移動で反転する。
- 4/5以上が一文で再説明できる。
- モーション軽減または静止代替でも原理を比較できる。

### C. SCALE & LIGHT ROOMS — 古典錯視を建築へ昇格する

#### #08 AMES ROOM — 実空間化

現行の全画面図解を、実際に入れる台形の部屋へ変える。固定視点では二人のシルエットの大きさが変わり、横から回り込むと床と壁の歪みが分かる。

競合では成立視点の実地確認が未完了だったため、ここは模倣ではなくPARALLAXの確実な学習設計で勝つ。

- 床マーカーからの成立
- 自由視点からの種明かし
- 部屋の実寸 / 投影サイズ表示
- 一人利用時は二体のシルエット、複数人時は将来拡張

一文:

> 同じ身長の二人が、部屋の端を替わるだけで巨人と小人になる。

#### #05 SHADOW SWITCH ROOM — 照明空間化

チェッカーシャドウを、壁面パネルではなく照明を切り替える小部屋へ移す。同じ色の床タイルを、影、周辺色、白色照明の三状態で比較する。現在の `#747985` の物理値表示は種明かしとして維持する。

一文:

> 違う色に見えた二枚は、照明を消すと同じ色だった。

### D. CLASSICS LAB — 一覧性と深掘りを両立する

#01〜#04、#06、#07を、六つのライブミニチュアが同時に見える実験ギャラリーへ再編集する。

- 一覧では各原理を5〜15秒で試せる。
- 興味を持った展示は既存の全画面実験へ入り、数値、ヒント、答え、リセットを使える。
- 直接リンクと現在の展示IDを維持する。
- 同じスライダーが続かないよう、ドラッグ、直接操作、注視、切替を隣接させない。

これにより、競合の2Dギャラリーの一覧性と、PARALLAXの深い操作を同時に持つ。

## 4. PERCEPTION PASSPORT と共有体験

### 4.1 展示結果

全12展示は、次のいずれかの `ExhibitOutcome` を返す。

- `measurement`: px、割合、秒、試行回数
- `comparison`: before / after
- `alignment`: 成立位置と投影誤差
- `sequence`: 短い状態遷移
- `observation`: 数値化しない自己申告

結果は診断値ではなく、その来館セッションの観察記録として扱う。

### 4.2 パスポート

4軸は順位付けや優劣を示さず、各軸の代表結果と「次に試す展示」を示す。

例:

- `PERSPECTIVE`: 「#09では基準視点から14cmの範囲で花を成立させた」
- `CONTEXT`: 「#01では同じ長さを8%短く調整した」
- `LIGHT`: 「#05では物理的に同じ色を異なる色として選んだ」
- `MOTION`: 「#07では静止点が消えるまで12秒だった」

完了条件は12 / 12だけにしない。4軸を一つずつ体験した時点で最初のパスポートを生成し、再訪で精度ではなく記録が増える設計にする。

### 4.3 共有形式

- 展示別 1200 × 630 px カード
- パスポート1枚
- 空間展示の8〜12秒リプレイ
- モーション軽減向けの二状態静止カード
- Web Share API、画像 / 動画保存、リンクコピー

初回公開ではブラウザ内生成と保存までとする。SNS固有SDKとアカウントは導入しない。共有リンクのOG画像が集客に必要と判断した場合だけ、静的サイトの範囲を超える小さな画像生成サービスを別判断する。

## 5. ナビゲーションの再設計

### 初回

1. タイトルから1操作で入館
2. アトリウムで最初の空間反転を目撃
3. 移動 / 視点 / 操作を文脈プロンプトで学ぶ
4. 最初の展示完了後にマップとパスポートを案内

### 探索中

- マップは常時呼び出せるが、自動で順路を強制しない。
- 各ゾーンに目的地名と遠景のランドマークを置く。
- 「おすすめ次作品」は未体験から一つだけ提示し、閉じられる。
- 同じ入力形式が連続しないよう、パスポート軸と体験形式から候補を選ぶ。

### 再訪

- セッション進捗は現在の `sessionStorage` から、バージョン付き `localStorage` へ移行する。
- 「続きから」「パスポートを見る」「自由に入館」をタイトルから選べる。
- 古い10展示の進捗はIDを維持して移行する。
- 共有URLからは展示だけでなく、推奨鑑賞位置と結果再現状態へ入れる。

## 6. 技術アーキテクチャの転換

### 6.1 展示モデル

`ExhibitDefinition` を次の責務へ拡張する。

```ts
type ExhibitPresentation = 'lab' | 'installation' | 'room'
type ExhibitOutcomeKind = 'measurement' | 'comparison' | 'alignment' | 'sequence' | 'observation'

type ExhibitDefinition = {
  // 現行フィールド
  presentation: ExhibitPresentation
  venue: 'atrium' | 'signature' | 'scale-light' | 'classics'
  outcomeKind: ExhibitOutcomeKind
  shareHook: string
  viewSpots?: ViewSpot[]
  recommendedAfter: ExhibitType[]
}
```

展示件数、進捗、マップ、完了表示の `/ 10` ハードコードはすべてカタログ由来へ変更する。

### 6.2 シーン

現在の単一 `MuseumEnvironment.tsx` を、ゾーン単位の遅延ロードへ分割する。

```text
src/scene/
  museum/
    MuseumShell.tsx
    ArrivalAtrium.tsx
    SignatureHall.tsx
    ScaleLightRooms.tsx
    ClassicsLab.tsx
  exhibits/
    SpatialParallaxBloom.tsx
    SpatialChromaticCorridor.tsx
    SpatialAmesRoom.tsx
    SpatialShadowRoom.tsx
    originals/
  interaction/
    SpatialExhibitController.tsx
    alignment.ts
    viewSpots.ts
```

- プリミティブ、シェーダー、インスタンシングを優先する。
- ゾーン外のアニメーションと計測を停止する。
- 照明とポスト処理はゾーン単位で予算化する。
- 外部3Dアセットは、手続き生成で表現できない場合だけ導入する。

### 6.3 状態

- `AppStage` に空間展示を明示し、全画面パネルと分離する。
- カメラ遷移、Pointer Lock、モーダル、展示離脱を一つの状態遷移へ集約する。
- `ExhibitOutcome`、パスポート、共有状態を展示のローカルstateから分離する。
- 永続データへschema versionとmigrationを持たせる。
- 結果カードを閉じても展示状態とカメラ位置を保持する。

### 6.4 視覚成立の検証可能性

空間錯視の成功判定を、見た目だけの手動確認へ閉じない。

- カメラから基準点を投影した画面上誤差
- 成立 / 非成立の固定カメラfixture
- FOV、アスペクト比、品質ごとの閾値
- 代表視点だけの限定的なスクリーンショット比較
- 一般描画と共有カードが同じ投影データを使用

## 9. 性能・品質予算

- 圧縮後配信ペイロードは現行の5MB上限を維持する。
- 初期画面で不要なゾーンと展示をロードしない。
- 高品質デスクトップは中央値55fps以上、p95フレーム時間33ms未満を目安にする。
- 低品質 / モバイルは中央値30fps以上を目安にする。
- 1展示あたりの常時draw callを事前に予算化し、反復形状はインスタンシングする。
- 結果カード生成はメイン描画を停止させず、失敗時はテキスト / SVG保存へフォールバックする。
- 高速点滅、強制カメラ揺れ、長い自動移動を使わない。

必須コマンド:

```bash
npm run lint
npm run typecheck
npm test
npm run build
npm run verify:size
npm run test:e2e
```

追加する検証:

- 空間成立の純粋関数テスト
- 各ゾーンの固定カメラ視覚fixture
- 旧進捗からV2へのmigration
- 12展示のデータ駆動E2E
- 共有対応 / 非対応 / キャンセル
- Pointer Lock解除、復帰、空間展示離脱
- reduced-motion / high-contrast / keyboard-only

## 12. PARALLAX 2.0 Definition of Done

- 12展示のうち6展示が館内の位置、建築、照明、移動のいずれかを成立条件にする。
- 4つのオリジナルが、それぞれ異なる一文と反転形式を持つ。
- #05、#08、#09、#10が全画面パネルだけに依存せず館内で完結する。
- CLASSICS LABで6原理を一覧比較し、既存深掘り画面へ移れる。
- 4軸の知覚パスポートが生成され、結果を保存できる。
- 直接リンク、旧進捗、共通操作、ヒント、答え、リセット、設定が移行される。
- デスクトップ、タッチ、キーボード、reduced-motion、高 / 低品質で主要フローが成立する。
- 圧縮後5MB予算、自動テスト、production build、視覚fixtureを通過する。
- 12〜20名の比較観察で定義した競争力、記憶、共有指標を満たす。
- 調査と同じ評価軸で91点以上となり、現行PARALLAXが勝っていた評価軸を一つも失わない。
